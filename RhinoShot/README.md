# RhinoShot — عکاسی هدایت‌شده‌ی ۹ نما + مدل سه‌بعدی چهره


> سورس کامل روی گیت‌هاب: **<https://github.com/ghahremany/rhinoshot>** — مخزن عمومی با کد کامل اندروید و iOS.

اپلیکیشن اندروید (Kotlin + Jetpack Compose) که عکس‌های استاندارد فرم کلینیک را
با راهنمای لحظه‌ای می‌گیرد: زاویه‌ی سر، فاصله، نور، تاری و کادر هم‌زمان کنترل
می‌شوند و شاتر به‌صورت خودکار در لحظه‌ی درست شلیک می‌کند.

از نسخه‌ی `0.3.0` یک **مدل سه‌بعدی قابل چرخش** از چهره هم ساخته می‌شود و یک
**منوی همبرگری** با صفحه‌ی «درباره‌ی اپ و توسعه‌دهنده» اضافه شده است.

نسخه: `0.3.3` · بسته: `com.rhinoshot.app` · حداقل اندروید: 8.0 (API 26)

> ⚠️ مدل سه‌بعدی از یک عکس تک‌چشمی ساخته می‌شود؛ برای **مشاهده و گفت‌وگو** است و
> جایگزین اندازه‌گیری دقیق جراحی (سنسور عمق / سی‌تی‌اسکن) نیست.

## ۰٫۳٫۳ — چیدمان صفحه‌ی عکاسی

* چهار کاشی **«چرخش»، «سر»، «لبخند» و «نور»** به چیپ‌های کوچکِ یک‌خطی تبدیل شدند
  (برچسب و مقدار کنار هم، گوشه‌ی گرد کامل، عرض مساوی) و در **پایین‌ترین ردیف صفحه** می‌نشینند.
* **بیضی راهنمای چهره بالاتر رفت** (۰٫۶۶ عرض / ۰٫۳۴ ارتفاع، مرکز ۰٫۳۳ ارتفاع) و ارتفاع
  قوس زاویه از ۷۶dp به ۵۶dp کم شد ⇒ پنل پایینی هرگز روی بیضی چهره نمی‌افتد.
* نسخه: `versionName = 0.3.3` / `versionCode = 6`.

## ۰. فهرست جدید نسخه‌ی ۰٫۳٫۰

### مدل سه‌بعدی قابل چرخش
* ورودی: همان landmarkهای MediaPipe که هنگام عکاسی ذخیره می‌شوند (`landmarks.json`)
* توپولوژی: مدل canonical مدیاپیپ — ۴۶۸ رأس و ۸۹۸ مثلث
  (فایل `app/src/main/assets/canonical_face_model.bin` با سربرگ `RHM1`)
* مقیاس: فاصله‌ی گوشه‌های بیرونی چشم = ۸۸ میلی‌متر؛ مرکز مدل روی نوک بینی
* نمایش: `GLSurfaceView` + GLES2 دستی (بدون وابستگی جدید) — چرخش با درگ، زوم با pinch
* امکانات: نمای اولیه، تمرکز روی بینی، نمایش سطح/تور، خروجی **OBJ**
* فقط کانال عمق (z) هموار می‌شود؛ نرمال‌ها از مثلث‌ها محاسبه می‌شوند

### منوی همبرگری (صفحه‌ی اصلی)
| گزینه | کار |
|-------|-----|
| نمایش سه‌بعدی چهره | باز کردن نمایشگر مدل (آخرین جلسه) |
| راهنمای استفاده | دیالوگ ۵ مرحله‌ای کار با اپ |
| درباره‌ی اپ و توسعه‌دهنده | نسخه، توسعه‌دهنده، قابلیت‌ها، حریم خصوصی، پروانه‌ها |
| حذف همه‌ی داده‌ها | پاک کردن کامل همه‌ی جلسه‌ها (با تأیید) |

### صفحه‌ی «درباره‌ی اپ»
اطلاعات برنامه (نام، نسخه، شناسه‌ی بسته)، اطلاعات توسعه‌دهنده، فهرست قابلیت‌ها،
متن حریم خصوصی، هشدار پزشکی و پروانه‌های MediaPipe / SceneKit.

> **توسعه‌دهنده:** محمد جواد قهرمانی — سازنده‌ی اپ «بامین تهویه»
> (سامانه‌ی محاسبات سرانگشتی تاسیسات، ۲۸ ماشین‌حساب، کاملاً آفلاین و فارسی)

## ۱. نماها (دقیقاً مطابق فرم کلینیک)

| # | نام | زاویه‌ی هدف | شرط اضافه |
|---|-----|-------------|-----------|
| ۱ | روبروی کامل | yaw = ۰° ، pitch = ۰° | حالت خنثی، لب بسته |
| ۲ | روبروی خندان | yaw = ۰° ، pitch = ۰° | لبخند (blendshape ≥ ۰٫۳۵) |
| ۳ | نیم‌رخ راست | yaw = ‎+۷۵° (±۱۲) | — |
| ۴ | نیم‌رخ چپ | yaw = ‎−۷۵° (±۱۲) | — |
| ۵ | سه‌رخ راست | yaw = ‎+۴۵° (±۹) | — |
| ۶ | سه‌رخ چپ | yaw = ‎−۴۵° (±۹) | — |
| ۷ | سر بالا | pitch = ‎+۳۰° (±۹) | چانه بالا، دید قاعده‌ی بینی |
| ۸ | سر پایین | pitch = ‎−۳۰° (±۹) | چانه پایین، دید پشت بینی |
| ۹ | کلوزآپ بینی | yaw = ۰° (±۱۴) | دوربین نزدیک، **ثبت دستی** |

> **قرارداد جهت:** «راست/چپ» از دید **خود بیمار** است؛ نیم‌رخ راست = نیم‌رخ سمت
> راست بیمار. همین برچسب در `session.json` و در EXIF هر عکس ثبت می‌شود تا در پرونده
> اشتباه نشود.

## ۲. جریان کار اپ

```
خانه ──(کد بیمار + رضایت‌نامه)──▶ عکاسی ──(۹ نما)──▶ بازبینی ──▶ خروجی/حذف
                                     ▲                        │
                                     └──── عکس دوباره ────────┘
```

### صفحه‌ی عکاسی
* پیش‌نمایش زنده‌ی CameraX + گاید بیضی + کادر تشخیص‌داده‌شده‌ی چهره
* نوار بالا: نمای جاری، راهنمای همان نما، پیشرفت ۹ مرحله
* نوار پایین: زاویه‌ی زنده، نشانگر گاید (هدف سبز / فعلی سفید)، فهرست ایرادها
* شاتر خودکار وقتی همه‌ی شرط‌ها سبز و به مدت **۹۰۰ میلی‌ثانیه** پایدار بماند
* دکمه‌ها: «ثبت عکس» (دستی)، «رد کردن»، «چرخش دوربین»، «تنظیم جهت‌ها»،
  «کنترل کیفیت: سخت‌گیرانه/آسان»

### شرط‌های سبزشدن (گیت‌ها)
| گیت | معیار | نوع |
|-----|--------|-----|
| چهره دیده شود | تشخیص MediaPipe | مسدودکننده |
| زاویه‌ی افقی | در محدوده‌ی تحمل نما | مسدودکننده |
| زاویه‌ی عمودی | در محدوده‌ی تحمل نما | مسدودکننده |
| لبخند | blendshape ≥ ۰٫۳۵ | مسدودکننده |
| فاصله | عرض چهره ۰٫۲۰–۰٫۷۲ و ارتفاع ۰٫۲۲–۰٫۸۸ کادر | مسدودکننده |
| مرکزیت کادر | \|cx−۰٫۵\| ≤ ۰٫۱۴ و \|cy−۰٫۴۵\| ≤ ۰٫۱۶ | مسدودکننده |
| کلوزآپ بینی | ارتفاع چهره ≥ ۰٫۴۲ کادر و بینی در مرکز | مسدودکننده |
| نور | روشنایی ۰٫۱۸–۰٫۹۴ (سخت‌گیرانه) | مسدودکننده |
| تاری | Tenengrad ≥ ۰٫۰۱۲ (سخت‌گیرانه) | مسدودکننده |
| چشم باز | blink < ۰٫۴ | هشدار |

راهنمای فارسی هر ایراد دقیقاً می‌گوید چه کار کنید، مثلاً
«سر را به سمت راست بچرخانید (۲۳° مانده)».

## ۳. خروجی و ساختار فایل‌ها

هر جلسه یک پوشه‌ی مستقل دارد:

```
Android/data/com.rhinoshot.app/files/Pictures/RhinoShot/<کد>_<YYYYMMDD_HHMMSS>/
├── 01_frontal.jpg              ۹ عکس با نام ثابت (ترتیب فرم)
├── 02_frontal_smile.jpg
├── ...
├── 09_nose_closeup.jpg
├── contact_sheet.jpg           کنتاکت‌شیت ۳×۳ با عنوان فارسی هر نما
├── session.json                متادیتای کامل جلسه
├── consent.txt                 رضایت‌نامه با زمان و کد بیمار
└── print_10x15/ | print_13x18/ نسخه‌های چاپی (۳۰۰dpi)
```

نمونه‌ی `session.json`:

```json
{
  "app_version": "0.3.3",
  "session_id": "R1234_20261025_142501",
  "patient_code": "R1234",
  "print_size": "10x15",
  "shots": [
    {
      "shot": "profile_right",
      "file": "03_profile_right.jpg",
      "title": "نیم‌رخ راست",
      "side": "نیم‌رخ راست بیمار",
      "yaw_deg": 74.2, "pitch_deg": -1.8, "roll_deg": 0.9,
      "smile": 0.02, "brightness": 0.51, "sharpness": 0.09,
      "face_width_ratio": 0.41, "face_height_ratio": 0.55,
      "auto_captured": true
    }
  ]
}
```

هر عکس هم metadata در EXIF دارد: مدل گوشی، نرم‌افزار، عنوان نما، تاریخ و
`UserComment` شامل yaw/pitch/smile.

## ۴. حریم خصوصی (پیاده‌سازی‌شده، نه فقط مستند)

* مجوز `INTERNET` و `ACCESS_NETWORK_STATE` که کتابخانه‌ی MediaPipe اضافه می‌کند
  با `tools:node="remove"` **حذف شده** — اپ از نظر فنی نمی‌تواند شبکه بزند.
* عکس‌ها فقط در حافظه‌ی خصوصی برنامه‌اند؛ انتقال به گالری یا برنامه‌ی دیگر فقط
  با یک لمس صریح کاربر انجام می‌شود.
* رضایت‌نامه پیش از شروع هر جلسه در `consent.txt` ثبت می‌شود (زمان، کد، نام، نوع خروجی).
* «حذف کامل جلسه» همه‌ی فایل‌ها (عکس، متادیتا، رضایت‌نامه) را پاک می‌کند.
* `android:allowBackup="false"` — داده‌ی بیمار در بکاپ سیستم نمی‌رود.

## ۵. نصب و اجرا

```bash
# نصب روی گوشی متصل
adb install -r RhinoShot-v0.3.3-release.apk
```

نصب دستی: فایل APK را در گوشی باز کنید و «نصب» را بزنید.

### کالیبراسیون (اجباری، یک‌بار برای هر گوشی)
در صفحه‌ی عکاسی دکمه‌ی **«تنظیم جهت‌ها»**:
1. بیمار مستقیم رو به دوربین → «ثبت زاویه‌ی صفر» (صفر شخصی سر حذف می‌شود)
2. بیمار سرش را به **راست خودش** می‌چرخاند → «ثبت جهت راست» (علامت خودکار)
3. بیمار چانه را **بالا** می‌برد → «ثبت جهت بالا»

نتیجه در SharedPreferences ذخیره و برای همه‌ی بیماران بعدی اعمال می‌شود.

### ساخت از سورس
```bash
unzip RhinoShot-v0.3.3-source.zip && cd RhinoShot
./gradlew assembleDebug      # خروجی: app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease    # خروجی: app/build/outputs/apk/release/app-release.apk
```
نیازمندی: JDK 17، Android SDK (platform 34 + build-tools 34)، Gradle wrapper همراه پروژه.
مدل MediaPipe در اولین بیلد خودکار دانلود می‌شود؛ در صورت نبود اینترنت دستی در
`app/src/main/assets/face_landmarker.task` بگذارید.

جزئیات کامل توسعه: `DEVELOPMENT.md`.

## ۶. محدودیت‌ها

* روی **گوشی واقعی** تست شود؛ شبیه‌ساز چهره‌ی واقعی ندارد.
* عکس‌ها **آینه‌ای ذخیره نمی‌شوند** (حالت واقعی).
* آستانه‌های نور/تاری برای دوربین‌های مختلف ممکن است نیاز به تیون داشته باشد.
* تصاویر برای **اندازه‌گیری جراحی دقیق** کافی نیستند؛ مدل سه‌بعدی از ۹ عکس
  تقریبی است و دقت بالا به فتوگرامتری یا سنسور عمق نیاز دارد.
* نمای «سر بالا/پایین» با گردن بیمار محدود می‌شود؛ برای زاویه‌های بیشتر از ۳۰°
  در فرم‌های خاص، مقدار `pitch` را در `data/Shots.kt` تغییر دهید.
